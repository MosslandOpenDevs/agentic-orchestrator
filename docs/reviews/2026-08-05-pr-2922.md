## 결론

루트 페이지의 새 제목과 푸터 생태계 링크는 정상적으로 렌더링되고, 영문·한국어 전환 및
모바일 줄바꿈도 동작합니다. 다만 “통합 title/share convention”이 공유 가능성이 가장 큰
네 종류의 상세 링크에는 적용되지 않습니다. 또한 새 생태계 링크의 접근성 이름과 새 탭
동작 안내를 보완해야 합니다.

병합 후 후속 수정 우선순위는 P2 한 건, P3 두 건입니다.

## 발견 사항

### P2-1. 상세 라우트가 새 메타데이터를 덮어써 통합 제목·공유 규칙이 적용되지 않음

위치:

- `website/src/app/layout.tsx:22-43`
- `website/src/app/ideas/[id]/page.tsx:12-23`
- `website/src/app/plans/[id]/page.tsx:12-23`
- `website/src/app/projects/[id]/page.tsx:12-23`
- `website/src/app/signals/[id]/page.tsx:12-23`

이번 변경은 루트 layout의 브라우저 제목, Open Graph 제목/사이트 이름, Twitter 제목을
`MOSS.AO — Agentic Orchestrator · Mossland`와 `Mossland`로 통일합니다. 그러나 네 상세
라우트의 `generateMetadata()`는 여전히 다음과 같은 기존 값을 반환합니다.

- `Idea - MOSS.AO`, `Plan - MOSS.AO`, `Project - MOSS.AO`, `Signal - MOSS.AO`
- `openGraph.siteName: 'MOSS.AO'`
- `twitter.card: 'summary'`

Next.js는 루트에서 페이지 방향으로 메타데이터를 합치며, 자식의 중복 필드가 부모 값을
대체합니다. `openGraph` 같은 중첩 객체도 얕게 교체되므로 자식 객체에 없는 루트
`images`까지 사라집니다.

배포 환경의 `https://ao.moss.land/plans/review-probe`에서 다음 값을 직접 재현했습니다.

```text
document.title: Plan - MOSS.AO
og:title: Plan - MOSS.AO
og:site_name: MOSS.AO
twitter:title: Plan - MOSS.AO
twitter:card: summary
og:image: 없음
```

따라서 홈 화면 공유는 새 규칙을 따르지만, 아이디어·플랜·프로젝트·시그널 상세 링크의
브라우저 탭과 공유 카드는 계속 기존 규칙을 사용합니다. 커밋이 선언한 통합 제목 규칙이
핵심 딥 링크에 적용되지 않는 기능 누락입니다.

권장 수정:

- 루트 `title`을 `default`/`template` 구조로 정의하고 자식 라우트는 `Plan` 같은
  브랜드 없는 제목만 반환합니다.
- 상세 라우트의 OG/Twitter 메타데이터 생성을 공용 helper로 중앙화합니다.
- 모든 상세 라우트에서 `siteName: 'Mossland'`와 공유 이미지가 유지되는지 메타데이터
  회귀 테스트를 추가합니다.

참고: [Next.js metadata merging 문서](https://nextjs.org/docs/app/api-reference/functions/generate-metadata#merging)

### P3-1. 사이트 이름과 설명이 접근성 이름에서 구분 없이 붙음

위치:

- `website/src/components/Footer.tsx:170-175`
- `website/src/components/Footer.tsx:178-187`

`{site.name}` 바로 다음에 설명 `<span>`이 오며, 두 텍스트 사이의 간격은 Tailwind
`ml-1.5`로만 만듭니다. CSS 여백은 접근성 이름에 문자를 추가하지 않습니다.

실제 배포 DOM에서 다음과 같이 결합된 텍스트가 재현됐습니다.

```text
BRIDGEGovernance OS
AlgoraAI Deliberation Lab
MOSS.AOAgentic Orchestrator
```

한국어에서도 `BRIDGE거버넌스 OS`, `MOSS.AO에이전트 오케스트레이터`처럼 동일하게
붙습니다. 화면에서는 여백이 보이지만 스크린리더 발음, 음성 명령, 텍스트 검색에서는
사이트 이름과 역할의 경계가 불명확합니다.

권장 수정:

- `{' — '}` 또는 실제 공백·구분 문자를 렌더링합니다.
- 또는 사이트 이름과 번역된 설명을 포함한 명시적 접근성 이름을 구성합니다.
- 렌더링된 링크/현재 항목의 accessible name을 영문·한국어로 검사하는 테스트를
  추가합니다.

### P3-2. 새 탭에서 열리는 동작을 링크 이름에서 알 수 없음

위치:

- `website/src/components/Footer.tsx:178-187`

BRIDGE와 Algora는 `target="_blank"`로 새 탭을 열지만, 보이는 텍스트와 접근성 이름에는
새 탭 동작을 알리는 정보가 없습니다. 키보드 및 스크린리더 사용자는 링크 실행 후 탐색
컨텍스트가 바뀐 사실을 예측하기 어렵습니다.

`rel="noopener"`는 opener 접근을 차단하므로 보안 설정은 올바릅니다. 이 항목은 동작
고지와 접근성 문제입니다.

권장 수정:

- 동일 탭 이동이 허용된다면 `target="_blank"`를 제거합니다.
- 새 탭이 제품 요구사항이면 번역된 “새 탭에서 열림” 문구나 아이콘과 스크린리더
  텍스트를 링크 이름에 포함합니다.

참고: [W3C H83](https://www.w3.org/WAI/WCAG22/Techniques/html/H83)

## 통합 상태 및 인접 이슈

AO의 사이트 순서, URL, 영문·한국어 설명은 BRIDGE 구현과 일치하며 두 외부 링크 모두
정상적으로 열립니다. Algora의 동반 변경은 PR 설명에서 아직 진행 중인 작업으로
명시됐고, 현재 배포된 Algora에는 역방향 생태계 바가 없습니다. 따라서 로컬 코드 결함으로
분류하지 않았지만, 3개 사이트 간 양방향 wayfinding 완료 여부는 동반 배포 후 확인해야
합니다.

또한 `website/src/app/layout.tsx:34`가 참조하는 `/og-image.png`는 저장소에 없고 현재
배포 URL도 HTTP 404를 반환합니다. 이 줄은 PR #2922에서 변경되지 않은 기존 문제이므로
이번 diff의 발견 사항에는 포함하지 않았습니다. 별도 SEO 후속 작업으로 추적하는 것이
적절합니다.
